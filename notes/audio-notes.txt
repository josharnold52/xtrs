HDA Quirks:

* On VirtualBox the capabilities for Volume Knob controls have an incorrect ID (not sure if this
  has been fixed in VBOX, but I have code that works around the problem if it exists and should
  safely no-op if it does not exit).   Look at comments in the capabilities code.

* On Asus NB (And probably all hardware using the same SCH chip), the DMAPOS for stream descriptors
  2 and 3 are at the location where we would expect to see 4 and 5.   T

  TODO: Detect the vendor ID and make this adjustment

* On VirtualBox you have to reset the root node of the code to make it initialize cleanly if it has
  been used before during the session.

* On real hardware you have to flush writes to the buffer descriptor lists and to the buffer contents
  in order for the audio hardware to see it.   TODO: Maybe do this for CORB and RIRB to be safe, although
  I haven't seen a problem with those

* On VirtualBox, the Current DMA Pointer advances in steps of 4096 samples!  (For 2-channel, 16bit , 48Khz format).
  Also, the VirtualBox WallClockCounter is essentially useless - it more or less onl advances when the DMA Pointer
  does, so it's resolution is something like 0.08 seconds.   Fortunately, rdtsc works, so we can use that as a clock,
  but we have to measure its frequency for it to be useful.   I think uclock probably also works.   In any case,
  I need to abstract out the high-res time source.
