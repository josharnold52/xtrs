* Real time improvements
  * First pass using uclock seems to work OK.  Occasionally I have thought I've seen variations in speed but unconfirmed.
    I added test code to try to check for this and could not reproduce.
  * Originally I thought maybe we should do delay checks at I/O time rather than in the z80 emulator loop.  This turned out
    to have a problem.  If the emulator time was far ahead of of real time, and an event came in (keystroke), you would have
    to wait for a long time for "real time" to catch up, which is a bad user experience.  So latest compromis is to coarser
    delay checks in the CPU loop and finer delay checks for IO that needs high accuracy.   This seemse to be working OK.
  * It looks like rdtsc is very constant on the netbook I tried it on so could replace uclock as something with more accuracy
    and less overhead.  The catch is I need to measure the TSC clock rate.   I've done this with high accuracy for one netbook
    and can now easily do it elsewhere with my tester program.   Perhasp use an ENV var or hardware profile to define the rate.
    If present, we use rdtsc for delay and not uclock.  ( Also should find all occurances of usleep and uclock and remove them?)
    The __asm pause loop seems pretty energy efficient but will have ot test using readtsc
  * Accuracy?
    * Requirement depends on which IO.  Sound should be very accurate.  Video can be relaxed.
    * Probably multipke thresholds. E.g. : 
      * within 20us don't worry about it. 
      * within ?? us do a spin loop (but only where accuracy is needed!).  TODO - Is there a low-energy spin technique for target CPU?
      * otherwise, do a sleep. TODO - What are dpmi sleep options?
    * Really only need for sound, video, and keyboard.   Disk, cassette, etc. should work off of T counts rather than real time
